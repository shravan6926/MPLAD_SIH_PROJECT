# MPLADS AI Monitor

Team: CodeDev's

Tagline:
"Smarter Monitoring. Earlier Detection. Better Accountability."

==================================================
1. PROJECT OBJECTIVE
==================================================

Build a complete AI-powered monitoring and analytics platform for MPLADS (Members of Parliament Local Area Development Scheme).

The platform will analyze MPLADS work, expenditure, recommendation, completion, MP allocation, payment, and financial summary data to identify:

- unusual expenditure patterns
- financial anomalies
- potential cost overruns
- unusual vendor/payment behavior
- potential duplicate works
- unusual work descriptions
- abnormal completion patterns
- low/high fund utilization
- compliance concerns
- high-risk projects/records
- state/district/constituency trends

The system is a DECISION-SUPPORT SYSTEM.

It must NEVER claim that a person or organization committed fraud merely because an ML model flags something.

Use language such as:

"Potential irregularity"
"Anomaly detected"
"Requires review"
"Potential duplicate"
"Unusual expenditure pattern"
"High-risk record"

Never automatically display:

"Fraud confirmed"
"Corrupt contractor"
"Fraudulent MP"

unless an authorized human investigator explicitly enters such a verified finding.

23. ML MODEL 3 — DUPLICATE WORK DETECTION
==================================================

This should be one of the major AI features.

Use:

- Work Description
- Category
- MP
- Constituency
- State
- IDA
- amount where useful

Technique:

TF-IDF + Cosine Similarity

Optionally use sentence embeddings later.

Do not compare every record against every other record blindly.

Use blocking first:

same state
same constituency
same category where available

Then similarity matching.

Output:

duplicate_candidate
similarity_score
matched_record
explanation

Example:

Work A:
"Construction of CC road from Village A to School"

Work B:
"Construction of cement concrete road from Village A towards school"

Similarity:

91%

Display:

"Potential duplicate work — review recommended."

Never claim confirmed duplication.

- unusually high expenditure/recommended ratio

or

==================================================

- Results are risk indicators, not proof of fraud.
- Missing data can affect predictions.
- Potential duplicate matches require human verification.
- ML models support human decision-making.
- Geographic visualization is shown only where reliable location information is available.
- Some analysis is based on historical patterns.

This will make the system more credible.

==================================================

Do not assume that every desired field exists in the current MPLADS datasets.

Build the application based on ACTUAL AVAILABLE DATA.
